## Game compatibility update

WineMetalGL 3.5.0 fixes rendering in several games, turns on x87 acceleration for 32-bit id Tech 4 games, and ships WineMetalGL Settings as a disk image that updates itself and applies game fixes.

### Games

- **Doom 3: BFG Edition** starts and runs, at 60 fps with x87 acceleration ([#25](https://github.com/metalsharp/WineMetalGL/issues/25), [#61](https://github.com/metalsharp/WineMetalGL/pull/61)). Its GLSL 1.50 shaders redeclare built-ins (`out vec4 gl_Position;`) and use compatibility ones without asking for the compatibility profile, as GL drivers allow. They now compile.
- **SpaceEngine** ([#35](https://github.com/metalsharp/WineMetalGL/issues/35)):
  - Jupiter, Saturn and the other ringed planets render ([#62](https://github.com/metalsharp/WineMetalGL/pull/62)).
  - The orbit lines render ([#63](https://github.com/metalsharp/WineMetalGL/pull/63)). Geometry shaders now match their inputs to the vertex shader's outputs by location, as GL does, not only by name.
- **OpenMW** (Morrowind), natively on the arm64 core ([#42](https://github.com/metalsharp/WineMetalGL/issues/42)):
  - Post-processing (`bloomlinear`) renders instead of a black window ([#64](https://github.com/metalsharp/WineMetalGL/pull/64)). Generic attribute 0 now reads `glVertexPointer`'s array, as other drivers do.
  - Shadows reach past the shadow map's far plane. Depth comparisons against 24-bit depth clamp their reference, as GL requires.
  - The statistics overlay's text (F3, osgText) shows ([#65](https://github.com/metalsharp/WineMetalGL/pull/65)).
  - `glCallList` is 3× faster (15.8 → 5.3 µs a call), which gives a stable 60 fps.
- **Quake 4** starts and runs at 60 fps ([#58](https://github.com/metalsharp/WineMetalGL/issues/58), [#59](https://github.com/metalsharp/WineMetalGL/pull/59)). WineMetalGL Settings applies its display-mode and `r_useSMP` fixes.

### x87 acceleration

Rosetta runs x87 floating-point code, which 32-bit games use for their math, as slow soft-float. With x87 acceleration, WineMetalGL starts [x87sidecar](https://github.com/athei/x87sidecar) when a 32-bit game loads OpenGL, in any Wine, CrossOver included ([#59](https://github.com/metalsharp/WineMetalGL/pull/59)). Quake 4's heaviest scenes went from 24 to 62 fps.

It is on by default for Quake 4, Doom 3 and Doom 3: BFG Edition ([#61](https://github.com/metalsharp/WineMetalGL/pull/61)). Turn it on for every 32-bit game with `WINEMETALGL_X87=1` (the Settings app's **x87 Acceleration** switch), or off for these too with `=0`.

### WineMetalGL Settings

The app now comes as a disk image (`WineMetalGL-Settings-3.5.0.dmg`) that carries a whole runtime ([#60](https://github.com/metalsharp/WineMetalGL/pull/60)):

- **Updates itself.** On launch it offers a newer release. It checks the download's signature and checksum, replaces itself, and updates WineMetalGL in every bottle and prefix it is installed in.
- **Game fixes**, on by default. It finds Quake 4, SpaceEngine and Wolfenstein: The New Order in your bottles and prefixes, and applies their fixes. It backs up each file it replaces to `~/Library/Application Support/WineMetalGL/Backups`.

### Changed

- **Shaders compile with Metal's safe math** ([#62](https://github.com/metalsharp/WineMetalGL/pull/62)). Arithmetic runs in the order the shader writes it, as GL drivers compile GLSL. Relaxed math reordered products that SpaceEngine keeps finite, and its gas giants came out NaN. Frame benchmarks do not change. Arithmetic-heavy shaders can be slower, and `WINEMETALGL_SAFE_MATH=0` restores relaxed math.

### Notes

- The first launch after updating recompiles shaders and pipelines, so expect normal compile stutter once.
