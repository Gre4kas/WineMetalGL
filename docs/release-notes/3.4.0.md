## Performance update

WineMetalGL 3.4.0 is a performance release. Games spend less CPU time per frame, stutter less while loading, and keep the GPU busy with drawing instead of waiting.

**DOOM (2016)** now runs at a stable **60 fps at native resolution, with no upscaling and no thermal throttling**, on a MacBook Air with M4.

### What to expect

Measured with the new performance probe (`tests/wine/perf_probe.py`) against 3.3.1. The figures are CPU time per frame, under Wine 11 on Apple M4.

- **Streaming buffers and textures.**
  - Per-draw uniform buffer updates are about 9× faster: 21.3 → 2.3 ms per 1000 draws.
  - Invalidating buffer maps are about 10× faster: 207 → 19 ms per frame, with Metal memory down from 826 to 68 MiB.
  - Uploads from pixel buffers no longer wait for the GPU: 1.1 → 0.4 ms.
- **Texture uploads in older formats.**
  - BGR, 565, 4444, 5551, luminance, float and `8_8_8_8` uploads are about 25× faster: 67 → 2.7 ms for nine 512² uploads. The results are bit-identical.
  - Auto-mipmapped textures are about 3× faster: 37 → 13 ms.
- **Older OpenGL games.**
  - Display lists are 44% faster.
  - Client-side vertex arrays are 27% faster, with no more CPU conversion.
  - Index buffer updates no longer stall on the GPU: 4.1 → 0.7 ms.
- **Fewer render-pass breaks and GPU stalls.**
  - Fence polling commits 70% fewer command buffers.
  - `glFlush` mid-frame no longer splits the frame: commits 31 → 2.
  - GPU timer queries commit 92% fewer command buffers.
  - `glReadPixels(GL_BGRA)` into a pixel buffer no longer waits: 4.6 → 0.6 ms.
  - A `glClear` followed by an upload no longer costs an extra pass.
  - Multisampled windows resolve without an extra pass.
  - `glInvalidateFramebuffer` now skips storing and reloading discarded attachments.
- **Separate shader objects.** Switching program-pipeline stages no longer recompiles pipelines: 23.6 → 1.5 ms per frame.
- **Faster loading.**
  - New on-disk shader cache: a program linked again in a later launch skips compiling and translating its shaders. Linking 60 programs takes 107 → 30 ms.
  - The pipeline cache is read in the background, so a large cache no longer holds up the first frames.

### New settings

- `WINEMETALGL_SHADER_CACHE=0` turns off the on-disk shader cache in `~/Library/Caches/WineMetalGL/shaders`.
- `WINEMETALGL_GPU_TIMERS=0` times `GL_TIME_ELAPSED` queries by committing command buffers, as before.

### Notes

- The pipeline cache now stops growing at 256 MB, down from 1 GB, so it always loads quickly.
- The first launch after updating builds the new shader cache, so expect normal compile stutter once.
